### 2. [camera] Auto-recal empty gate is self-referential and the AUTO_RECAL_MAX cap uses a per-deck MEAN, so a single-spot corruption (~99 gray levels) passes every guard and poisons the reference
`lane_node/camera.py:485`

Hunt (1): the only gates on auto-recalibration are (a) WSL_CAM_AUTO_RECAL=1 (camera.py:105), (b) is_empty_deck() on the SAME detector whose reference may be wrong (pin_detect.py:510-530 via check_empty_reference pin_detect.py:578-584), and (c) max_divergence <= AUTO_RECAL_MAX (camera.py:485-490). There is NO machine-state gate: nothing ties the check to an actual FSM known-empty moment (no production caller exists — lane_node.py never calls self_check_empty; the only entry points are the CLI --check-empty at camera.py:735-740, runnable at any instant, and future daemon wiring the docstrings merely suggest). Two concrete poisoning paths pass all gates: (1) MEAN dilution — spot_divergence returns the mean of |diff| over 10 pins (pin_detect.py:344-346) and check_empty_reference discards the per-pin diffs (pin_detect.py:582), so a single cap ROI darkened by ~65-99 gray levels (shadow, grease, rag, sweep-board edge) gives mean 6.5-9.9: over EMPTY_DIVERGENCE_MAX=6 (flagged) yet under AUTO_RECAL_MAX=CONF_BAND=10 (camera.py:106-107) -> recalibrated. That spot reads strongly 'down' (margin ~-137, not low-confidence since low-conf requires |margin| < 10), so empty_confirmed stays True. After recal, a genuinely empty deck reads value = normal - dark_ref ~ +99 > DET_THR 38 at that spot -> a permanent phantom STANDING pin corrupting every future score. (2) Self-reference — if the reference is already misaligned (bumped camera) or was force-captured badly, standing pins sampled off-cap read 'empty with high confidence', and check_empty_reference then confirms the poisoned reference as healthy (divergence ~0) or recalibrates onto a racked deck. Also: _auto_recalibrate keeps only ONE .bak generation (camera.py:506-511) — a second auto-recal overwrites the last-good reference's backup with the first poisoned one, destroying the recovery path.

**Fix:** Gate the refusal cap on per-pin max |diff| (the data already exists in spot_divergence's diffs dict — return it through check_empty_reference instead of discarding it), require N consecutive confirmed-empty checks across separate grabs before persisting, add a machine-state precondition when daemon-wired (only in the FSM's post-sweep/pre-spot window), and rotate .bak files (e.g. keep 3 generations or never overwrite an existing .bak from an auto-recal).

### 3. [camera] Shared DualDeckDetector state (last_detail, _last_sig) is read/written outside the capture lock — concurrent detect_lane() for both lanes can trust a LOW-CONFIDENCE mask
`lane_node/camera.py:373`

PairCamera advertises concurrent detect_lane() as the supported pattern for both lanes throwing within the settle window (camera.py:124-127), and lane_node.py delivers exactly that: each DIELL schedules _settle_capture_emit which runs detect_current_pins via asyncio.to_thread (lane_node.py:241), so two worker threads call detect_lane(21) and detect_lane(22) on the SAME PairCamera/DualDeckDetector concurrently. Only grab_frame() is serialized; self._detector.detect_lane(frame, lane_id) at camera.py:367 and the low-confidence gate read of self._detector.last_detail at camera.py:373 run unlocked. detect_detail mutates shared instance state: self.last_detail (pin_detect.py:481) and self._last_sig/_stale_count (pin_detect.py:437-447). Interleaving: thread A's pass is low-confidence, thread B's confident pass overwrites last_detail before A reads it -> A returns its low-confidence mask as trusted and the daemon AUTO-SCORES an uncertain mask — the precise failure the gate exists to prevent (the reverse interleaving only causes a safe spurious awaiting_manual). The stale-frame guard is also racy: both threads can hash-compare against the old _last_sig before either writes, letting a byte-identical stale frame score. Same class of race exists in self_check_empty's save/restore of last_detail (pin_detect.py:577-579 via camera.py:464-467): if it ever runs concurrently with a scored pass it can restore a STALE detail over the scoring pass's fresh one.

**Fix:** Make detect_detail return the detail and have camera.detect_lane use the returned dict instead of re-reading detector.last_detail (a one-line data-flow fix removes the gate race); protect _last_sig updates with a lock or serialize the whole detect pass under PairCamera._lock.
